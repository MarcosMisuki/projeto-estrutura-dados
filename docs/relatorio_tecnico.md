Projeto Prático Individual: Aplicação de Estruturas de Dados
Curso: Tecnologia em Análise e Desenvolvimento de Sistemas (3º Semestre). Disciplina: Estrutura de Dados. Docente: Prof. Me. Heber Castro. Autor: Marcos Paulo Mathias Misuki. Tema Escolhido: Tema A - Redes (Equipamentos e conexões).

Este relatório detalha a modelagem e a implementação de uma aplicação de terminal desenvolvida em linguagem C para o gerenciamento de equipamentos de rede e suas interconexões topológicas. O sistema foi construído para resolver um problema prático através da integração de múltiplas Estruturas de Dados: Árvores Binárias de Busca (BST) e Grafos como componentes centrais, apoiados por pilhas e filas dinâmicas encadeadas, bem como algoritmos de ordenação sobre vetores auxiliares. O objetivo primordial é garantir a consistência rigorosa dos dados. A arquitetura modulariza os Tipos Abstratos de Dados e gerencia manualmente a alocação e liberação de memória, tratando limites de capacidade, validação de entradas seguras e operações de reversão (rollback) em caso de falhas, conforme os requisitos técnicos exigidos.

A entidade base do sistema é estruturada utilizando um registro que armazena um ID inteiro e arrays de 80 caracteres para nome, tipo de equipamento e localização. Optou-se pela utilização de arrays estáticos de caracteres em vez de ponteiros para alocação dinâmica. Esta escolha garante que as cadeias textuais de até 79 caracteres úteis sejam armazenadas contiguamente na memória junto com o ID. Isso melhora a localidade de cache e simplifica drasticamente o gerenciamento de memória, evitando vazamentos por esquecimento de liberação nos campos de texto, além de facilitar a cópia estruturada durante o processo de ordenação. O ID é estritamente tratado como inteiro positivo.

A Árvore Binária de Busca atua como o índice principal do sistema, organizando os registros hierarquicamente com base em sua chave primária (ID). A inserção e a busca operam de forma recursiva, navegando à esquerda para IDs menores e à direita para maiores. A lógica de remoção engloba os três casos fundamentais. Para um nó sem filhos, ele é isolado e liberado. Para um nó com um filho, ele é removido e seu único filho assume sua posição. Para um nó com dois filhos, optou-se pela substituição do nó pelo seu sucessor em-ordem, que é o menor elemento da subárvore direita. Os dados estruturais do sucessor são copiados para o nó alvo da remoção e, em seguida, aciona-se a remoção recursiva do nó sucessor original. A complexidade temporal ideal das operações da árvore é O(log n), dependente de sua altura. Como o escopo não exigiu balanceamento automático, a estrutura está sujeita ao seu pior caso: se os usuários inserirem IDs de forma estritamente ordenada, a árvore degenerará para uma lista encadeada, resultando em complexidade O(n).

O Grafo modela as conexões topológicas não direcionadas entre os equipamentos de rede cadastrados. Ele foi modelado utilizando uma Matriz de Adjacência acompanhada de um mapeamento compacto de índices. Como os IDs inseridos são arbitrários, criou-se um vetor de mapeamento para traduzir o ID real para um índice de 0 a 99, garantindo tempo de consulta das arestas de forma direta e eficiente para grafos densos. A sincronia entre a árvore e o grafo é crítica, sendo que o cadastro de um equipamento cria obrigatoriamente o seu vértice no grafo. A operação inicia inserindo os dados na árvore e, em seguida, tenta-se alocar o vértice no grafo. Caso o grafo já tenha atingido o teto operacional de 100 vértices, a inserção falha e o sistema executa o rollback, removendo o nó da árvore recém-criado para não manter vértices desencontrados. A função de listar equipamentos alcançáveis aplica a Busca em Largura (BFS), utilizando uma fila dinâmica própria para orquestrar a descoberta de vértices. A ordem estrita de visitação é armazenada em uma lista encadeada, que insere nós exclusivamente no fim.

Para exibir a relação de equipamentos ordenados por nome, o sistema aciona a extração dos dados da árvore sem corromper sua topologia. Um vetor dinâmico de estruturas é alocado na memória, e um percurso prefixado popula esse vetor com cópias dos dados. Foi implementado o Insertion Sort para a ordenação, que, apesar da complexidade quadrática, possui baixa sobrecarga arquitetural e é eficiente para vetores pequenos e quase ordenados. O algoritmo utiliza ordenação lexicográfica sensível à caixa, com desempate pelo ID numérico crescente, liberando a memória do vetor auxiliar imediatamente após a impressão.

As ações transformadoras de estado, como cadastro e exclusão, são registradas em uma Pilha Dinâmica de histórico. Implementada via encadeamento de nós, não possui limite de capacidade exceto o hardware. A leitura de histórico para as últimas cinco ações é executada por um ponteiro auxiliar temporário que percorre o encadeamento sem disparar ações destrutivas.

A estabilidade da interface foi assegurada contra comportamentos não intencionais utilizando métodos seguros de leitura combinados a varreduras para remoção de quebras de linha. Quando a entrada supera os 79 caracteres alocados, o resíduo depositado no buffer é sumariamente descartado através de um laço de leitura, evitando que vazamentos corrompam o fluxo do menu principal. A bateria de testes validou o bloqueio de duplicidade de IDs, o sucesso de remoções complexas sem perda de ramificações e a resistência do sistema a sobrecargas textuais sem gerar falhas de segmentação.

Em conclusão, a arquitetura consolidada cumpre a prerrogativa de vincular fisicamente uma representação hierárquica por IDs a uma representação de conectividade topológica por malha. As implementações periféricas confirmam a viabilidade funcional do modelo integrado num ambiente restrito, validando as diretrizes de gerenciamento limpo de ponteiros. Declaro, por fim, que as modelagens propostas são autorais e derivam da compreensão técnica do escopo exigido. Para a elaboração do fluxo lógico da árvore e a estrutura do relatório formativo, foi utilizado apoio da Inteligência Artificial como base orientativa conceitual, para estudos e correções de erros, não substituindo a construção lógica central da implementação individual.
